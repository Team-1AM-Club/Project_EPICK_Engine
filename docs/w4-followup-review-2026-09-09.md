**개발 보조 도구의 검토이며 사람의 정답 승인을 대신하지 않는다.** 기존 점수·정답·프롬프트는 변경하지 않았다.
이번 검토에서 새 모델 호출은 수행하지 않았다.

## 채점기 해석에서 보완할 점

[stage_eval.py](../epick_w4/stage_eval.py)의 `score_question`은 custom 기준을 ID와 label의 조합으로 식별한다.
정답 label과 다르면 인용 구간을 비교할 기준도 찾지 못하므로 `question_quote_valid=false`가 된다.
따라서 현재의 `QUESTION_GROUNDING_FAILED`에는 **원문 인용 문제와 custom 표현 불일치가 함께 포함**된다.
문자 그대로의 인용 정확도 91.67%라는 뜻으로 설명하면 부정확하다.

B에서 ID·필수 정보·확인 상태가 같고 원문 인용 및 같은 ID의 필수 인용 구간을 만족하면서 label만 다른
검토 대상은 총 6건이다. Gemma 26B 2건, Gemma 12B 1건, Qwen3-14B 1건, Qwen3.5-9B 2건이다.
Qwen3-14B의 ‘사용자 중심 기능 제안’, Qwen3.5의 ‘이용자 관점의 개선 제안’도 표현 변형으로 볼 수 있다.
Qwen3.5의 ‘사용자 불편 해결’은 제안보다 넓은 표현이므로 같은 기준으로 인정할 범위를 더 명시해야 한다.
**ID와 인용이 같다는 조건만으로 모든 custom label을 자동 정답 처리할 수는 없다.**

다음 채점 버전에서는 원문 인용의 일치 여부, 부정·제외 조건을 보존한 인용 범위, 기준의 의미 일치를
별도 항목으로 표시하는 것이 적절하다. label 동의어를 변경한다면 별도 정답 버전으로 기록하고 새 사례로 확인해야 한다.
이번 v3 성적과 선정 조건을 소급해서 바꾸지는 않았다.

또한 `unsafe_fact_admissions`는 **매칭 계약 검증을 통과한 응답만** 비교한 수치다.
계약 위반 응답은 정답률 0점과 필수 검증 실패로 처리되지만, 해당 응답의 fact 오채택 수는 이 지표에 더해지지 않는다.

| 보완 설정 B | 전체 판단 | 계약 유효·오채택 진단 대상 | 진단 대상 안의 사용 불가 fact 채택 |
|---|---:|---:|---:|
| Qwen3.5-9B | 44 | 43 | 0 |
| Qwen3-14B | 44 | 38 | 3 |
| Gemma 12B | 44 | 32 | 0 |
| Gemma 26B | 44 | 44 | 1 |

Gemma 12B의 0건을 전체 44개 응답에 위험한 판단이 없었다는 뜻으로 설명할 수 없다.
다만 계약 실패가 이미 모델 선정의 필수 실패 조건이므로 이 집계 한계가 운영 모델의 자동 선정을 허용하지는 않는다.
[원본 대조 JSON](../output/review-v3-20260909/followup-review.json)에 A/B 8개 조합의 진단 범위와 표현 검토 사례를 보관했다.

## 코드 검증과 사용 결정

`SemanticMatcher._candidate_result`가 중복·누락·다른 경험 ID와 사용 불가 fact의 참조를 거부하는지,
추출에서 지시문·혼합·계획 구간이 완료 ACTION으로 들어가지 않도록 검사하는지 확인했다.
코드가 받는 구조와 모델의 의미 판단은 구분해야 한다. 이번 검토에서 런타임 코드 변경은 하지 않았다.
전체 테스트를 다시 실행해 **197개 통과**를 확인했다. 이 테스트는 모의 응답과 HTTP 검사이며 새로운 실제 모델 측정은 아니다.

현재 판단은 **Gemma 12B를 추출 검토 후보, Gemma 26B를 문항·매칭 검토 후보로 유지하고 운영 선정은 보류**하는 것이다.
두 모델을 조합한 통합 호출은 아직 측정하지 않았다. 팀 공유용으로는 이미 실행한
[Gemma 26B 협업 시연](../output/local-evaluation-v3-20260909-26b-r2/gemma4-26b-qat/live-collaboration.json)을 사용하고,
실행 완료가 추천 정확도 확정을 뜻하지 않는다고 설명한다.

이 검토 기록과 기존 실제 응답·성적표, 소스, 테스트, 재개 요약을 현재 작업 디렉터리의 백업에 포함한다.
노트북에서는 저장된 요약과 현재 파일 상태를 대조한 뒤 이어가며, 모델 가중치와 가상환경은 별도로 준비한다.
