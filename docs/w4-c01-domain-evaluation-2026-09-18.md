# C01 기업 기준의 의미·분야 연결 보완과 실제 재평가

후속: [판단 분리·새 사례 비교·W1 연결 시연 결과](w4-staged-result-2026-09-18.md). 아래는 같은 날 앞선 평가 기록이다.

기존 달리기 경험을 기업의 기술 학습 진술에 연결하던 오류는 **이번 실제 API 재실행에서 나타나지 않았다.** 새 가상 사례 7개에서는 모델별로 다른 오류가 남아, **운영 모델은 계속 `WITHHELD`**다. 프롬프트 보완과 작은 표본의 재실행 결과이며, 오류가 일반적으로 제거됐다는 뜻은 아니다.

## 변경과 검증 범위

[c01_detail.py](../epick_w4/c01_detail.py)의 판단 지침을 `w4-c01-content-checks/0.2`로 올렸다. 기업 진술의 분야·대상, 실제 학습 행동, 기간·반복, 본인 수행 여부를 각각 확인하도록 했다. 반복 연습이나 기존 도구 사용만으로 학습을 추론하지 않으며, 일반적인 조건에 다른 기업 진술의 분야 제한을 덧붙이지 않도록 구분했다.

이전 실제 비교에 사용한 추론 코드와 대조했을 때 변경된 엔진 파일은 위 프롬프트와 가상 입력 허용 목록 2개다. 모델 가중치를 학습시키거나 추천 정렬식을 바꾼 작업은 아니다. 새 가상 원문과 기업 기준의 정확한 해시만 허용 목록에 추가했다.

- 실제 평가에 사용한 완료 호출: **41회** = 새 경험 추출 7회 + 네 모델의 판단 28회 + 기존 API 회귀 6회.
- 최종 재개 실행에서 새 호출 27회, 동일한 보존 응답 사용 14회. 모의 응답을 실제 추론 점수에 섞지 않았다.
- 중단 이전 별도 이력: 완료 응답 4회, Qwen 14B 시간 초과 1회, Gemma 12B 응답 생성 중 중단 1회. 이를 포함한 이번 작업의 요청 시도는 **47회**다. 이 6회는 최종 비교에서 제외했고 원본 기록은 남겼다.
- 전체 로컬 테스트 **323개 통과**, 실패·오류·생략 0. 가상 HTTP 시연 2개 통과(모의 호출 12회, 실제 호출 0회).
- 실제 판단 요청 28개의 전송 내용을 대조해 같은 실제 추출 결과가 전달됐음을 확인했다. 실행 중 고정한 소스 46개도 일치했다.

첫 실행은 모델 응답 이후 내부 추천 결과에 API 전용 필드를 요구한 실행기 검사 오류로 멈췄다. API 전체 Schema 검사를 실제 API 회귀 단계에 두도록 수정하고, 완료된 14개 응답은 입력 일치 확인 후 재사용했다. 이 실행기 오류를 모델의 의미 판단 오류로 채점하지 않았다.

## 평가 방법

첫 모델 호출 전에 문항·원문·정답 초안·프롬프트를 고정했다. **Gemma 12B가 실제로 분류한 원문 구간을 네 판단 모델에 동일하게 전달**하고, 기존 추천 코드로 각 모델의 결과를 조립했다. 판단 입력을 정답 분류로 대신하지 않았다. 중단과 실행기 수정 과정에서도 입력·프롬프트·정답 초안은 바뀌지 않았다.

새 기업 진술은 “소프트웨어 개발 기술을 꾸준히 학습한 경험”이라는 **명시적인 가상 기준**이다. 실제 SK하이닉스 인재상을 새로 확인한 자료가 아니다. 기존 달리기 회귀에서는 이전의 가상 기업 기준과 원문을 그대로 사용했다.

| 새 사례 | 구별하려는 내용 |
| --- | --- |
| 01 예약 API | 소프트웨어를 꾸준히 학습하고 입력 검증에 적용 |
| 02 로그 조회 도구 | 학습한 내용을 코드에 적용하고 문서 작성 |
| 03 스페인어 안내 | 실제 학습과 문서 작성은 있으나 소프트웨어 학습은 아님 |
| 04 회의실 예약 | 학습·코드 적용은 동료가 수행함 |
| 05 미래 계획 | 앞으로 학습·적용할 계획을 완료한 행동과 구분 |
| 06 달리기 기록 프로그램 | 운동을 소재로 했어도 실제 소프트웨어 학습·개발은 인정 |
| 07 기존 프로그램 실행 | 도구 사용만으로 학습·코드 적용을 만들어 내지 않는지 확인 |

기업 조건은 `코드 적용 AND (입력 검증 OR 문서 작성)`이다. 사례 03의 일반 문서 작성은 부분 조건으로 인정할 수 있지만, 코드 적용이나 전체 조건 충족을 뜻하지 않는다. 같은 조건이 출처 두 곳에 반복돼도 채점은 하나의 의미 항목으로 계산했다. 미래 계획에는 미리 정한 `NOT_SHOWN` 또는 `AMBIGUOUS`를 인정하고 `SUPPORTED`는 인정하지 않았다.

정답은 사람이 승인하지 않은 작성자 초안이다. 전문성 문항 하나의 작은 평가이며 다른 문항·긴 원문·실사용 전체 성능을 대표하지 않는다. GPU의 다른 프로그램 사용량이 달라졌으므로 이번 결과로 속도 우열을 판단하지 않는다.

## 실제 결과

추출은 Gemma 12B 한 모델로 측정했다. 구간 분류 전체 일치는 **24/26(92.31%)**, 주체·진술 상태·불확실성 표시는 각각 **26/26**이었다. 나머지 두 구간은 미래 계획을 초안의 `ACTION` 대신 `GOAL`로 분류한 차이다. 미래 계획이라는 `PLANNED` 상태는 맞게 유지했고, 사용할 수 없는 행동을 완료 사실로 받아들인 경우는 0건이었다. 원문 복사와 위치 보존은 코드의 기능이므로 이를 LLM 정확도 수치로 계산하지 않았다.

아래는 **사전 고정한 v1 초안**에 대한 판단 결과다. 네 모델 모두 7개 응답의 구조 검사를 통과했다.

| 판단 모델 | 문항 상태 21항목 | 기업 진술 7항목 | 세부 조건 21항목 | 근거 충분성 49항목 | 기업 오탐: 모델 → 코드 검사 후 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Qwen 3.5 9B Q4 | 76.19% | 42.86% | 76.19% | 69.39% | 9 → 4 |
| Qwen 3 14B Q6 | 80.95% | 42.86% | 85.71% | 75.51% | 7 → 3 |
| Gemma 4 12B QAT | 85.71% | **100%** | 95.24% | 91.84% | 1 → 1 |
| Gemma 4 26B A4B QAT | **95.24%** | 71.43% | **100%** | 91.84% | 2 → 1 |

문항 상태는 모델 원응답의 판정이다. 코드 검사 후에는 Gemma 12B의 문항 상태 일치가 90.48%로 바뀌었다. 전체 복합 조건의 최종 상태 일치는 Qwen 9B 57.14%, Qwen 14B 85.71%, Gemma 두 모델 100%였다. **전체 조건을 맞혀도 개별 진술이나 부분 조건의 오판이 사라지는 것은 아니다.**

Gemma 12B는 이번 기업 진술 연결에서 가장 좋았지만, 사례 07의 기존 프로그램 실행을 ‘배운 내용을 코드에 적용’한 근거로 잘못 인정했다. 미래 학습 계획도 문항의 일부에서는 `SUPPORTED`라고 했으나, 그 부분은 코드가 `AMBIGUOUS`로 낮췄다.

Gemma 26B는 문항·세부 조건 점수가 가장 높았지만, 스페인어 학습을 소프트웨어 학습 진술에 연결했다. 미래 계획을 연결한 경우는 코드가 낮췄다. 따라서 현재 근거로 **12B 추출 → 26B 판단 조합을 운영 확정할 수 없다.** 이 조합 자체의 실제 연결은 이번 평가에서 실행했다.

Qwen 두 모델에도 분야 오연결과 기존 도구 사용을 학습으로 확대하는 오류가 남았다. 이전의 다른 평가에서 Qwen이 좋았던 결과와 모순되는 비교는 아니다. 입력·평가 과제가 달라졌다.

근거 충분성에는 정답 초안의 인용 범위 문제도 확인됐다. 사례 06에서 Qwen 9B와 Gemma 26B는 필요한 학습 구간 `u2`를 포함했지만, 관련된 본인 구현 구간 `u4`를 추가 인용해 감점됐다. 이 추가 인용은 적절한 문맥으로 볼 수 있어 실제 의미 오판과 구분해야 한다. 두 모델에 동일한 범위 수정을 적용한 **사후 검토 제안**에서는 근거 충분성이 각각 71.43%, 93.88%가 된다. 원래 v1 점수는 보존했고, 새 모델 호출이나 새 사례 검증으로 표시하지 않았다. 이 수정으로도 기업 오탐과 선정 보류 결론은 달라지지 않는다.

Gemma 26B가 사례 07의 활용을 `AMBIGUOUS`로 남긴 것은 초안의 `NOT_SHOWN`과 다른 보수적인 상태 선택이다. 이를 사실을 지어내어 `SUPPORTED`로 승인한 오류와 동일하게 해석하지 않는다. 해당 상태 기준도 팀 검토 대상이다.

## 기존 오류의 실제 API 재검증

W4 API에 가상 요청을 넣어 **Gemma 12B 추출 3회 → 판단 3회 → 코드 정렬**을 새로 실행했다. HTTP 200, 출력 0.3 Schema와 별도 품질 검사를 통과했다.

| 경험 | 문항 판정 | 추천 순서 | 충족으로 표시된 기업 연결 |
| --- | --- | ---: | ---: |
| 파일 검증 도구 학습·적용 | 직접 부합 | 1 | 4개: 동일 기준의 출처 2곳 |
| 달리기 훈련 | 확인 필요 | 2 | **0개** |
| 과학관 접수 협업 | 확인 필요 | 3 | 0개 |

달리기 훈련에 붙었던 잘못된 기술 학습 연결이 이번 결과에는 없다. 2·3위는 확인 필요 상태이며, 두 경험 사이의 의미 있는 품질 우열을 입증한 순위가 아니다.

호스트 인증·경험 조회와 W3 상태는 가상 구현을 사용했다. 실제 모델 호출은 localhost의 llama.cpp 서버에서 수행했다. 팀 W1 서버·DB를 연결한 운영 시연은 아니다. 문항 부합 판정과 기업 연결을 따로 반환하며, 기업 연결에 별도 순위 가산점을 주지 않는다.

```powershell

```

재개 시에는 `--resume-from`으로 이전 실행 폴더를 지정한다. 추론 엔진·가상 입력·프롬프트·정답·모델 설정이 같은 경우에만 완료된 HTTP 기록을 재사용하며, 실패하거나 중단된 모델 실행은 새로 측정한다. 원본 폴더를 덮어쓰지 않는다.
