# W4 경험별 호출과 분리 평가 v2

이 문서는 v2 구조와 당시 측정 기록이다. 최신 자료·프롬프트와 실행법은 [v3 검토·재평가](w4-review-v3-2026-09-09.md)를 참조한다.

[2026-09-08 실제 네 모델 성적·오류·추천 시연](w4-local-evaluation-v2-2026-09-08.md)을 함께 참조한다.

## 구현한 흐름

가상 경험 원문 → LLM의 구간 분류 → 코드의 원문·위치 연결 → 문항 기준 분석 → 경험별 LLM 판단 → 코드의 근거 검사·추천 정렬.

- `SemanticMatcher.evaluate()`는 문항 기준과 **경험 하나**를 전송한다. 경험 N개면 문항 분석 1회와 매칭 N회다. 원문 추출까지 하면 경험별 추출 N회가 추가된다.
- 서버 처리와 평가기는 `single_candidate_payloads()`를 공유한다. 다른 경험의 ID·버전·근거를 반환하면 실패한다.
- 각 응답을 받은 즉시 검증한다. 호출·참조 검증 실패를 규칙 추천으로 대체하거나 성공한 것처럼 숨기지 않는다.
- 사용할 수 있는 본인 행동이 없는 경험은 `NEEDS_CONFIRMATION`으로 남긴다. 기록 부족을 경험 부재로 확정하지 않는다.
- 최종 정렬은 후보 상태 → 충족 기준 수 → 근거 종류 수 → 기업 맥락 연결 → 경험 ID 순서다. LLM이 순위나 가중치를 만들지 않는다.
- 검색은 현재 목록 범위다. 최대 20개 제한은 유지한다. 대규모 자료는 Graph·Vector 검색으로 먼저 줄이는 연결이 남아 있다.

## 형식 검증과 의미 평가의 구분

로컬 JSON Schema는 입력의 ID와 목록 길이를 제한한다. 정답 역량·부합 여부·본인 기여 여부는 넣지 않는다.
따라서 형식 성공률은 **모델과 출력 제약을 함께 적용한 시스템**의 지표이며 모델의 자유 생성 능력 점수가 아니다.

| 구분 | 확인하는 것 | 실패·오답 처리 |
|---|---|---|
| JSON 파싱 | JSON 객체로 읽을 수 있는가 | 실패도 전체 요청 수에 포함 |
| 출력 구조 | 필드·타입·열거값이 맞는가 | 구조 오류로 별도 표시 |
| 참조 계약 | 경험·버전·fact·criterion ID, 중복·누락, 인용이 맞는가 | 의미 정답으로 인정하지 않음 |
| 문항 기준 | 기준 ID·지원 범위 확인 여부가 맞는가 | 인용 길이와 분리한 정답률·F1 |
| 답변 구성 | ROLE/ACTION/RESULT 요구를 찾았는가 | 런타임 규칙 보정 전 모델 답변 채점 |
| 문항 인용 | 실제 원문이며 정답의 완전한 의미 구간을 포함하는가 | 더 긴 인용 허용, 의미 구간을 잘라낸 인용 불허 |
| 경험 매칭 | 관련성·fact 사용 가능 여부·기준과 행동의 연결이 맞는가 | 경험별 전체 일치율과 연결 F1을 별도로 표시 |
| 위험한 근거 채택 | 정답상 사용할 수 없는 팀·부정·계획·지시문을 사용 가능하다고 했는가 | 필수 검증 실패로 표시 |

`question_quote`의 더 긴 인용은 정답 초안의 최소 의미 구간을 온전히 포함해야 한다.
단순 부분 문자열 일치만으로 올바른 의미라고 인정하지 않는다. 다른 타당한 짧은 표현은 정답 변형으로 먼저 검토·등록해야 한다.
모델이 사람처럼 의미를 판정하는 자동 채점은 사용하지 않는다.

## 원문 추출 별도 평가

원문 추출에는 문항이나 회사 정보를 보내지 않는다. 모델은 고정된 원문 줄의 종류·주체·서술 상태·문제점을 분류한다.
발췌 문자열과 시작·끝 위치는 코드가 원문 그대로 복사한다. 모델이 부정어를 잘라내거나 수치·기술명을 다시 쓰는 출력 형식을 제공하지 않는다.

- 종류: ROLE, ACTION, RESULT, GOAL, PERIOD, OBSTACLE, REFLECTION, CONTEXT.
- 지표: 구간 전체 일치, 종류 micro F1, 주체 정확도, 진술 상태 정확도, issue 정확도.
- 별도 필수 검사: 출력 누락·형식 오류, 팀/타인의 행동을 본인 행동으로 채택, 부정·계획·가정을 완료 사실로 채택.
- 원문·위치가 정확히 복사됐다는 사실은 그 행동의 실제 수행 여부나 모델의 분류 정확도를 입증하지 않는다.

## 평가 자료와 실험 조건

문항 16개(기존 개발 사례 8개 + 새 사례 8개), 매칭 요청 28개(각 요청에 경험 1개),
추출 경험 8개·원문 구간 33개다. 각 항목을 한 번씩 실행하므로 비교 호출은 **모델당 52회**다.
통합 시연은 별도로 원문 4개와 협업·학습 문항 2개를 호출한다.

새 사례에는 부정된 행동, 타인·팀 기여, 미래 계획, 제외 역량, 리더십, 도전, 데이터 안의 AI 지시, 지원 범위 밖 문항을 포함했다.
새 사례의 정답은 해당 모델 응답을 보기 전에 작성했다. 이후 응답을 보고 정답을 바꾸지 않는다.
다만 작성자는 같은 개발 보조 도구이므로 사람의 독립 검토를 마친 평가 자료는 아니다. 정답·정책은 `DRAFT`로 유지한다.

공통 생성 조건은 temperature 0, seed 42, 최대 출력 4,096토큰, thinking 비활성화다.
컨텍스트는 8,192토큰으로 고정하며 llama.cpp의 자동 메모리 배치와 1,536MiB 여유 목표를 사용한다.
모델당 파일 형식·양자화가 다르므로 모델 원본의 성능을 완전히 통제한 실험은 아니다.
각 모델의 최적 설정을 탐색한 결과도 아니다.

시간은 실제 HTTP 요청의 경과 시간이다. 모델 파일 검사·초기 로딩 시간은 제외한다.
GPU 사용량은 약 2초 간격으로 관측한 **장치 전체 사용량**이며 다른 앱 사용분을 포함한다. 정확한 모델 단독 최대 메모리 측정은 아니다.

## 실행과 기록

이미 설치된 네 모델을 다시 읽어 해시만 갱신할 때:

```powershell
python scripts/prepare-evaluation-v2.py --models-only --models-dir 'C:\.lmstudio\models'
```

원문부터 추천까지 시연만 실행할 때:

```powershell
python scripts/run-local-evaluation.py --v2 --demo-only --candidate qwen35-9b-q4 --output-dir output/my-v2-demo
```

네 모델을 비교하고 각각의 통합 시연도 저장할 때:

```powershell
python scripts/run-local-evaluation.py --v2 --output-dir output/my-v2-comparison
```

출력 폴더는 새 경로여야 한다. 기존 결과는 덮어쓰지 않는다.
현재 실행기는 이전에 받은 임시 폴더의 llama.cpp b10859 실행 파일을 사용한다. 다른 PC에는 해당 런타임도 준비해야 한다.
대형 모델 파일은 프로젝트나 Google Drive 폴더에 복사하지 않는다.

출력에는 평가 데이터·정답·정책 스냅샷, 실행 전 코드 해시, 실제 모델 파일 해시,
실제 HTTP 요청·응답·오류, 사례별 점수, GPU 관측 기록, 통합 시연 입력·출력이 포함된다.
종료 시 이 실행기가 시작한 서버만 정리한다.

## 모델 선택과 API 연결

`collect_stage_run()` / `evaluate_stage_runs()`는 `JsonClient` 계약을 따른다.
상용 API가 준비되면 그 어댑터로 같은 가상 평가 요청을 수집할 수 있다. 현재 실행은 로컬 모델이며 상용 모델을 대신한 성적이 아니다.

`select_evaluated_client()`는 v2 정책도 인식한다. 실제 검토된 정답·정책으로 원본 응답을 다시 채점하고,
참조 계약·문항 근거·위험한 fact 채택 검사를 통과한 모델 중 문항/매칭 50:50 점수의 단독 최고점을 선택한다.
정답 미검토, 모의 응답, 필수 검증 실패, 동점이면 임의로 모델을 선정하지 않는다.

원문 추출의 성적은 그 종합 점수에 합산하지 않는다. 선택 메타데이터의 `unevaluated_stages=["extraction"]`은
문항·매칭 점수로 추출 모델의 품질까지 승인한 것이 아님을 나타낸다.
실제 운영에 쓸 추출 모델은 별도 추출 보고서와 위험한 근거 채택 여부도 검토해야 한다.

API 키 발급·백엔드 인증 구현·Graph/Vector 연결·실제 사용자 데이터 전송은 이번 로컬 비교에 포함하지 않는다.
