# D-05: W1·W3·W4 계약과 사용 정책 합의 요청

상태: **PENDING — 공동 합의 전**. 2026-09-09에 받은 「W4 서비스 전달물 검토」의 미결 항목을 정리한 요청서다. 이 문서의 항목·상태 이름은 확정된 upstream 스키마가 아니다. 검토서가 인용한 W3 원문 `Docs/03_W3_KNOWLEDGE.md`는 이번 작업에서 직접 확인하지 못했다.

W4의 현재 [소비 계약](w4-service-handoff.md)은 `w3-w4-projection/0.1-draft`다. 아래 결정과 버전이 명시된 실제 샘플을 받은 뒤 어댑터·스키마·테스트에 반영한다. 현재 REAL 데이터 차단을 유지한다.

## 계약 결정표

담당은 회의 참여 제안이며 확정 배정이 아니다. 모든 행의 결정 상태는 PENDING이다.

| 주제 | 현재 W4가 가진 정보 / 부족한 정보 | 공동으로 결정하고 받을 내용 | 참여 제안 |
|---|---|---|---|
| 원문·추출 버전 | `source_version_id`, 본문 SHA256만 있고 실제 추출 revision 없음 | `extraction_revision_id`의 생성·갱신 규칙, SourceVersion과의 관계, 재추출 전후 샘플 | W3·W4 |
| 표현·정규화 | Evidence에 quote·문자열 locator만 있음 | representation/normalization 버전 키, locator가 가리키는 표현·추출 revision, 오프셋 단위와 정확한 인용 규칙 | W3·W4 |
| 현재 제한 | 로컬 `usage_status`와 서버 `context_version` 재검사만 있음 | 현재 restriction 상태·revision·조회 주체, 변경 전파, 처리 중 차단, 저장된 추천·캐시 무효화와 재분석 선택 | W1·W3·W4 |
| 색인 ACK | 성공·실패·재처리와 색인 revision 없음 | ACK payload, 상태 전이, 성공으로 인정할 버전 조합, 실패/지연/재처리 시 조회·W4 실행 허용 여부 | W1·W3·W4 |
| Claim·Requirement | 로컬 VERIFIED/USABLE/RESTRICTED/WITHDRAWN 분기 | 실제 enum과 의미, 검증/사용 가능/철회 전이, Claim과 명시 요건 구분, 필수·우대의 표현 | W3·W4 |
| 부분 추출 범위 | 출처에 PARSED/UNPARSED/PARTIAL만 있음 | 검증된 범위와 누락 범위, Claim별 근거 위치, 필수 범위 표시, 부분 추출 후 추가 추출의 버전 관계 | W3·W4·제품 담당 |
| 결과·작업 상태 | W4 `processing_status`, W1 대응은 미승인 | 제한 완료·입력 필요·변경 감지·재실행의 W1 Job 상태와 사용자 안내, 중복 요청 처리 책임 | W1·W4·제품 담당 |

`context_version`이나 전체 문맥 해시는 위 의미별 revision 및 ACK를 대신하는 확정 계약이 아니다. 현재 구현에는 지속 저장된 추천·검색 캐시 무효화 기능이 없다. 삭제·제한 변경에 대한 저장소 처리와 이미 전송된 요청 취소 범위도 호스트가 명시해야 한다.

## 날짜·첨부·부분 추출 결정표

현재 보수적 처리를 유지하고 아래 선택을 공동 결정한다. 날짜 미상과 비정상 파싱은 **해당 출처의 Claim/Requirement를 제외**한다. `required=true`인 SourceReview가 USABLE이 아니면 **기업 근거 전체를 보류**한다. 기업 근거를 쓸 수 없어도 일반 문항의 경험 추천은 제한 상태로 가능하며 지원 자격 미달 판정이 아니다.

| 상황 | 현재 처리 | 합의할 선택과 필요한 입력 |
|---|---|---|
| 발행일 null | 해당 근거 제외, 날짜 미상 보존 | 제외 유지 또는 검증된 범위만 제한 표시로 사용. 적용 가능한 공고·직무 scope와 날짜 검증 책임 필요 |
| 부분 추출 | PARTIAL 출처의 근거 제외 | 검증된 Claim만 제한 사용할지, 필수 범위 누락이면 기업 매칭을 중단할지. 누락/필수 범위의 명시 방식 필요 |
| 첨부 상태 | 진단용 ATTACHMENT_UNPARSED로 제한 전달 | 미제공·다운로드 실패·미지원·파싱 실패·부분 추출의 구분과 재수집/재추출 주체, 각 상태가 영향을 주는 범위 |
| 필수 자료 미완료 | 기업 근거 전체 보류 | 필수 자료/범위의 지정 주체, 전체 차단 또는 제한 추천 여부와 W1 안내 |
| restriction·철회 | 현재 제공된 문맥/정책이 바뀌면 후속 호출·반환 차단 | 이미 저장된 추천·캐시의 무효화 범위, 변경 통지 지연, 사용자 재분석 선택과 Job 상태 |

검토서의 `NOT_PROVIDED`, `FETCH_FAILED`, `UNSUPPORTED`, `PARSE_FAILED`, `PARTIALLY_EXTRACTED`는 첨부 상태의 **제안 예시**다. 합의 전에 운영 enum으로 추가하거나 W3 상태와 임의 대응하지 않는다.

어떤 정책에서도 수집일을 발행일로 대신 채우거나, 누락 자료의 내용을 추정하거나, W2 placeholder를 Claim/Requirement로 승격하지 않는다. W4가 미분석 첨부를 우회 파싱해 W3 검증을 대신하지 않는다.

## 합의 완료 시 전달받을 자료

1. 채택한 계약 버전, Schema/타입, 필드별 소유 팀과 갱신 규칙.
2. 동일 출처의 정상·재추출·철회·색인 실패·재처리·부분 추출·날짜 미상 샘플. 각 샘플의 예상 W4 사용 범위와 W1 결과 상태.
3. 인증 사용자 범위로 프로젝트·EpisodeVersion·Snapshot·현재 제한을 조회하는 W1 구현체와 테스트 방법.
4. 제품 담당이 승인한 날짜/첨부/부분 추출 결정, 사용자 안내와 재분석 정책.

## 이후 실제 W1 구현체로 확인할 수용 사례

아래는 **미실행**이다. 가상 Backend 회귀 테스트 통과와 구분한다.

| 사례 | 확인할 결과 |
|---|---|
| 타 프로젝트, 삭제·제외 경험, 오래된 Snapshot | 실제 조회·권한 처리에서 모델 호출 전에 차단 |
| 처리 중 restriction·동의·권한 변화 | 후속 모델 호출과 결과 반환 차단, 저장된 결과/캐시는 합의한 방식으로 무효화 |
| 재추출/정규화 변경과 과거 Evidence 혼합 | 합의한 정확한 버전 키로 거부, 올바른 새 Snapshot 재분석 선택 |
| ACK 실패·지연·재처리 | 합의한 실행·대기·오류 상태와 재시도 동작 |
| 날짜 미상·부분 추출·첨부 실패 | 합의한 사용 범위·제한 안내·작업 상태, 누락 내용 추정 없음 |
| 실제 데이터에 SYNTHETIC 표시 | 현재 가상 전송 경로에서 실제 본문 차단 |

계약 합의 → 어댑터·Schema 및 회귀 사례 반영 → 실제 W1 구현체 통합 → CI 산출물 검토 순서로 닫는다. 운영 모델 선정과 실제 기업 연결 프롬프트의 정확도 평가는 별도 미완료 항목이다.
