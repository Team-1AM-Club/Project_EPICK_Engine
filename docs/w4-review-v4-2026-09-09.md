# W4 v4 재평가·단계별 모델 연결 결과

요청한 순서 중 **채점기 개선, 새 사례 평가, 두 모델 조합의 실제 시연, SK하이닉스 문항별 상세 점검 연결**을 진행했다.
운영 모델 확정과 팀 서버의 인증·DB·검색 연동은 남아 있다. 정답은 사람 미검토 초안이고 모든 판단 후보가 필수 검사 중 하나 이상에서 실패했다.

실제 모델 비교 336회, 첫 조합 시연 52회, 상세 판단 보완 확인 35회로 **새 로컬 호출 423회**를 보관했다.
테스트 **216개 통과**, 두 비교 설정의 원본 대조·재채점과 두 통합 시연의 재계산·인용 대조가 모두 통과했다.
테스트 통과와 기록 재현은 모델의 모든 의미 판단이 옳다는 뜻이 아니다.

## 1. 채점기를 분리한 내용

새 정책 `w4-stage-policy/0.3`, 채점기 `w4-source-context-meaning/0.3`을 사용한다.
기존 `w4-stage-policy/0.2`와 과거 점수는 보존했다.

| 검사 | 판정 |
|---|---|
| 원문 인용 | 실제 문항에 그대로 있는 연속 구간인지 |
| 문맥 보존 | 인용이 같은 기준의 사전 고정한 의미 구간을 포함하는지 |
| 기준 의미 | 요구한 기준·확인 필요 여부를 맞혔는지 |
| 답변 구성 | 역할·행동·결과 요구를 맞혔는지 |
| 경험 판단 | 사실 사용 가능성·근거 연결·관련 상태를 모두 맞혔는지 |
| 위험 근거 진단 | 계약이 거부된 JSON에서도 식별 가능한 fact의 잘못된 허용·참조를 집계 |

예를 들어 인용은 원문 그대로여도 ‘배운 지식을’에서 멈춰 ‘적용’ 조건을 빠뜨리면 인용 일치와 문맥 점수가 갈린다.
기준 label 차이 때문에 원문 인용까지 오답으로 세던 문제도 분리했다.
형식 실패가 난 응답의 근거를 진단하되 그 응답을 고쳐 성공 처리하지 않는다.
이번 매칭 응답에서는 각 설정·모델별 72개 fact 판정을 모두 진단했다. 계약 유효 응답 수는 별도 지표다.

custom label은 실행 전 고정한 동의 표현 목록을 허용한다. 자유로운 모든 동의어를 자동 판정하는 장치는 아니다.
새 응답에서 목록에 없는 label 7건은 [표현 검토 목록](../output/local-ab-v4-20260909/question-review-queue.json)으로 분리했다.
특히 Gemma 26B의 ‘사용자 관점 제안’, ‘절차의 재현성’은 등록 표현과 조사 차이로 보인다.
이 두 건을 확정된 의미 오류라고 부르지 않으며 팀 검토가 필요하다. **이를 보고 정답을 수정하거나 기존 점수를 올리지는 않았다.**
아래 성적에는 이 제한이 반영되어 있으므로 소수점 차이로 운영 우열을 확정하지 않는다.

## 2. 새 가상 사례의 실제 비교

v3에서 본 사례는 이번 평가에 포함하지 않았다. **문항 12개·경험 판단 24개·원문 6경험/30구간**을 응답 수집 전에 고정했다.
모델당 설정별 42회, 4모델 × 2설정으로 336회다. 반복은 각각 1회다.
대상은 Qwen3.5 9B Q4, Qwen3 14B Q6, Gemma 4 12B QAT, Gemma 4 26B A4B QAT의 설치 파일이다.
A는 기존 프롬프트·출력 스키마 0.2, B는 보완 0.3이다. **새 채점기·원문·문항·정답은 A/B에서 같다.**
코드 차이는 `llm_prompts.py`, `output_schemas.py`, `local_client.py`의 설정이다. 프로토콜 해시는 각 설정에 맞게 기록했다.

| 모델·설정 | 문항 완전 정답 | 경험 판단 완전 정답 | 두 항목 50:50 | 원문 구간 전체 일치 |
|---|---:|---:|---:|---:|
| Qwen 9B A | 75.00% | 50.00% | 62.50 | 46.67% |
| Qwen 9B B | 83.33% | 37.50% | 60.42 | 43.33% |
| Qwen 14B A | 66.67% | **70.83%** | 68.75 | 63.33% |
| Qwen 14B B | 75.00% | 50.00% | 62.50 | 70.00% |
| Gemma 12B A | 83.33% | 50.00% | 66.67 | 73.33% |
| Gemma 12B B | 83.33% | 58.33% | **70.83** | **83.33%** |
| Gemma 26B A | 75.00% | 62.50% | 68.75 | 63.33% |
| Gemma 26B B | 66.67% | **70.83%** | 68.75 | 73.33% |

**Qwen이 경험 판단을 잘했다는 이전 해석은 틀리지 않았다.** 이번에도 Qwen 14B A가 해당 항목 공동 최고다.
Gemma 26B B가 전체 기준에서 최고라고 말할 수 없다. 추출 점수도 문항·매칭 점수에 합산하지 않는다.
Gemma 12B B는 추출 25/30 일치이며 추출 필수 검사를 통과했다. Gemma 26B B도 추출 필수 검사를 통과했다.
나머지 설정은 추출 계약 또는 위험 사실 허용 검사에 실패했다.

문항·매칭의 운영 필수 검사는 모든 후보가 실패했다. 대표적으로:

- Qwen 14B A는 타인·부정 행동을 사용 가능하다고 처리한 사례와 역할 배정을 수행 행동으로 인정한 사례가 있었다. 잘못된 사실 허용 3건, 위험 참조 1건이다.
- Gemma 26B B는 ‘장비 담당자로 배정됐다’는 문장을 책임감의 수행 행동으로 인정했다. 잘못된 사실 허용·참조가 각각 1건이다.
- Gemma 12B B는 사용 불가 판정한 사실을 연결하는 등 위험 참조 4건과 계약 실패가 남았다.
- Qwen 9B B는 매칭의 위 위험 건수는 0이지만 문항 인용의 의미 구간을 놓친 사례가 있고 매칭 완전 정답은 9/24다.

인용 정확성·근거 연결·모델 평가의 정답은 서로 다른 문제다. 이 결과는 작은 가상 자료의 관측치이며 일반 사용자 데이터 성능을 확정하지 않는다.
상용 API는 호출하지 않았다. 모델·코드 해시, 실제 HTTP 요청/응답, 필수 검사 실패를 모두 남겼다.

## 3. 두 모델을 실제로 연결한 시연

**Gemma 12B B 추출 → Gemma 26B B 판단 → 코드 순위 결정**을 실제 실행했다.
첫 시연은 가상 원문 7개 추출 7회, 기존 협업·학습 추천 10회, 상세 문항 판단 35회로 총 52회다.
추출 서버를 종료한 뒤 판단 서버를 적재했으므로 두 모델을 동시에 GPU에 올리지 않았다.
이 조합은 요청한 검증 대상이자 실험 후보이며 운영에서 선정된 우승 조합은 아니다.
특히 상세 판단 프롬프트는 새 계약이므로 일반 매칭의 70.83%를 상세 문항 정확도라고 옮겨 쓰지 않는다.

일반 추천의 [협업 시연](../output/staged-demo-v4-20260909/live-collaboration.json)과
[학습 시연](../output/staged-demo-v4-20260909/live-learning.json)은 모두 `COMPLETED_WITH_LIMITATIONS`로 끝났다.
팀 전체 행동만 있는 경험은 확인 필요로 남았다. 원문 추출은 [실제 추출 결과](../output/staged-demo-v4-20260909/live-extraction.json)에 있다.

## 4. SK하이닉스 상세 문항 적용

기존 초안을 [실행용 문항 자료](../epick_w4/criteria_catalog.json)로 읽어 5문항·10점검을 적용했다.
원본 [작성 당시 초안](../samples/criteria/skhynix-it-2026-march.draft.json)은 당시 상태와 수동 예제를 보존한다.
새 경로는 `POST /w4/recommend-from-raw`이며 일반 `/w4/recommend`를 호출했다고 이 초안이 자동 적용되는 것은 아니다.

점검마다 원문 전체 구간을 인용하고, 필요한 종류·본인 주체·실제 수행 상태를 검사한다.
학습 지속에는 ACTION과 PERIOD, 본인 목표에는 SELF/GOAL, 협업 기여에는 목표·본인 행동·결과 맥락이 필요하다.
이 검사는 최소 근거 검사다. 의미 연결이나 인과를 코드가 독립 입증하지 않는다.
내용 점검의 충족 개수를 별도 가산점으로 더하지 않는다.

첫 시연에서 일회성 학습을 ‘꾸준히 배우고 적용하는 태도’에 인정한 점과 소프트웨어 경험을 놓친 점을 발견했다.
가상 사용자가 선택한 해당 주제의 학습·기간/반복·활용 조건을 명시하고, 소프트웨어 구현·테스트·수정 및 프로젝트 경험의 직무 연결 범위를 보완했다.
상세 프롬프트 0.2로 **같은 실제 추출 결과를 재사용해 35회 새 판단 호출**을 했다.
초기 결과를 덮어쓰지 않았으며 이 재확인은 새로운 평가 자료에서의 일반화 성적이 아니다.

| 상세 문항 | 보완 후 실제 확인한 동작 | 결과 |
|---|---|---|
| 전문성 | 기간·반복이 있는 학습은 직접 부합. 기간 없는 Python 학습은 일부 부합 | [expertise](../output/staged-demo-v4-20260909-r2/detailed-expertise.json) |
| 협업 | 본인 조율 행동은 인정. 공동 목표와 기여 연결이 부족하면 추가 확인 | [teamwork](../output/staged-demo-v4-20260909-r2/detailed-teamwork.json) |
| 도전 | 10km 목표에 8km까지 달린 경험도 목표·난관·지속 근거로 직접 부합 | [challenge](../output/staged-demo-v4-20260909-r2/detailed-challenge.json) |
| 자기소개 | 선택 주제의 ‘꾸준함’ 근거 없는 일회성 학습은 확인 필요 | [self_description](../output/staged-demo-v4-20260909-r2/detailed-self_description.json) |
| 직무 경험 | API 코드와 도서관 예약 코드 경험의 소프트웨어 연결을 인정 | [job_experience](../output/staged-demo-v4-20260909-r2/detailed-job_experience.json) |

보완 후 70개 점검은 SUPPORTED 22, NOT_SHOWN 45, AMBIGUOUS 3이었다. 이는 **모델 판정 분포이며 정확도 점수가 아니다.**
예제는 검토를 위해 후보 7개를 모두 반환한다. API 샘플은 상위 3개를 요청한다.
협업에서 목표가 없는 일부 부합 후보가 인과 연결 확인이 필요한 후보보다 앞설 수 있다. 상태 우선 정렬의 결과이며 사람 검토가 필요한 정책 선택이다.
근거 종류가 더 많이 인용됐다는 이유로 같은 상태 안에서 앞설 수도 있다. 근거의 양과 경험의 질을 동일시하지 않는다.

공식 문구·글자 수·필수 여부는 고정하지 않았다. `SUPPORTED`는 원문 기록의 뒷받침이며 사실성·지원 자격의 확정이 아니다.
새 코드의 모의 안전성 검증과 실제 시연을 분리했고, 누락된 사용자 주제는 임의의 성격 추정 없이 `NEEDS_INPUT`으로 반환한다.

## 5. 남은 연동과 품질 승인

[서비스 브랜치 조사와 연결 계약](w4-backend-integration.md)에 확인한 커밋과 API 예제를 정리했다.
`feat/BE`는 폴더 구조와 빈 파일만 있어 실제 API·인증·DB 명세를 참고할 수 없었다.
엔진의 HTTP 및 서로 다른 모델 주입은 프로세스 내부 테스트로 검증했다. 팀 운영 서버에는 연결하지 않았다.

다음 순서는 팀의 정답·표현 검토 → 위험 사실 허용 및 과도한 거부 오류 보완 → 새 사례에서 필수 검사 통과 확인 → 운영 조합 선정이다.
서비스 명세가 준비되면 인증·프로젝트/경험 조회·버전·Graph/Vector 후보 검색을 연결하고 테스트 서버에서 검증한다.
실제 데이터 전송은 여전히 차단했다. 키를 요청하거나 실사용 자료를 모델에 보내지 않았다.

## 재현

프로젝트 루트에서 실행한다. 기존 출력 경로는 덮어쓰지 않으므로 새 경로를 지정한다.

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -q
.\.venv\Scripts\python.exe scripts/run-local-ab-v4.py --output-dir output/my-v4-comparison
.\.venv\Scripts\python.exe scripts/audit-local-v4.py --directory output/my-v4-comparison --profile a
.\.venv\Scripts\python.exe scripts/audit-local-v4.py --directory output/my-v4-comparison --profile b
.\.venv\Scripts\python.exe scripts/run-staged-demo.py --output-dir output/my-staged-demo
.\.venv\Scripts\python.exe scripts/audit-staged-demo.py --directory output/my-staged-demo
```

평가 파일은 이미 고정되어 있어 `prepare-evaluation-v4.py`를 다시 실행하면 덮어쓰기를 거부한다.
A 설정 준비에는 보존한 `output/review-v3-20260909/v2-source/`가 필요하다. 모델과 llama.cpp 실행 파일은 PC에 별도로 있어야 한다.
기본 로컬 추론 조건은 context 8192, output 4096, temperature 0, seed 42, thinking off다.
메모리 여유 목표는 26B 4096MiB, 나머지 1536MiB다. 다른 프로그램의 GPU 사용량이 변하므로 속도 순위를 단정하지 않았다.

기록 감사: [A 168회](../output/local-ab-v4-20260909/a-audit.json), [B 168회](../output/local-ab-v4-20260909/b-audit.json),
[첫 통합 52회](../output/staged-demo-v4-20260909/audit.json), [보완 판단 35회](../output/staged-demo-v4-20260909-r2/audit.json).
감사 스크립트는 저장 응답을 재계산하며 모델에 새 요청을 보내지 않는다. 코드·입력·출력 재현과 원문 위치만 확인하며 사람의 의미 검토를 대체하지 않는다.
