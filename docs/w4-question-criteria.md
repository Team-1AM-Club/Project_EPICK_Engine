# W4 문항별 경험 선택 기준 초안

상태: **공식 서식 조건을 확정하지 않고 사용하는 개발·검토 초안**. 작성일: 2026-09-08.

사용자의 “고정하지 않고 진행하자”에 따라 2단계의 기준을 정리했다. 대상은 기존 자료와 연결되는 2026년 3월 SK하이닉스 신입 IT 채용(R260521)이다. [문항 확인 기록](w4-target-questions-2026-09-08.md)을 근거로 하며, 기계가 읽을 수 있는 설계 자료는 [기준 JSON](../samples/criteria/skhynix-it-2026-march.draft.json)에 있다.

## 미확인 조건을 다루는 방법

공식 문항 전문, 글자 수, 필수 여부와 해시태그 개수 제한은 `null`로 둔다. `null`은 미확인이며 제한 없음, 선택 항목, 0자를 뜻하지 않는다. 채용 매체에서 관찰한 600자·선택 항목·해시태그 2개 표기는 이전 조사 기록에서 출처와 함께 보존하고, 강제 조건으로 옮기지 않는다.

미확인 조건으로 경험을 제외하거나 순위를 낮추지 않는다. 글자 수는 향후 작성할 답변의 형식 조건이므로, 경험 원문의 길이를 자르는 기준으로도 사용하지 않는다. 요청받은 문항에 대해 추천하며 모든 지원서 항목에 답해야 한다고 가정하지 않는다.

아래 내용 점검 항목도 수정 가능한 해석 초안이다. **기업의 공식 배점표나 모델 평가 정답이 아니다.** 실제 지원서 원문이 들어오면 차이를 기록하고 문항별 기준을 다시 검토한다.

## 문항별로 찾을 내용

| 문항 | 경험에서 점검할 핵심 내용 | 함께 확보할 원문 정보 | 출처 |
|---|---|---|---|
| 전문성 | 구체적인 전문 분야, 지속적인 학습, 실제 활용 | 학습 방법·반복 또는 기간·적용 결과·근거 자료 | [CATCH 공개 문항](https://www.catch.co.kr/NCS/RecruitInfoDetails/541607/) |
| 협업 | 공동으로 이루려던 일, 본인의 협력 유도 행동, 목표에 대한 기여 | 당시 상황·참여자 관계·결과·소회 | [잡플래닛 문항 안내](https://www.jobplanet.co.kr/contents/news-8065) |
| 도전 | 본인이 정한 높은 목표, 어려움 속에서 이어간 노력 | 목표 설정 과정·난관·대응·결과·소회 | [잡코리아의 해당 상반기 문항](https://www.jobkorea.co.kr/company/1496894/keyword) |
| 자기소개 | 사용자가 표현하려는 가치관·개성·강점 중 선택한 주제 | 그 주제를 뒷받침하는 본인의 행동·맥락 | [잡코리아의 해당 상반기 문항](https://www.jobkorea.co.kr/company/1496894/keyword) |
| 직무 경험 기술 | IT 업무와 연결되는 실제 수행 내용 | 활동 범위·본인 역할·구체적 작업·결과 | [잡플래닛 문항 안내](https://www.jobplanet.co.kr/contents/news-8065), [IT 직무 출처 검증](skhynix-source-verification-2026-09-08.md) |

출처가 직접 요청하는 내용과 W4가 근거를 확인하기 위해 추가한 점검은 JSON에서 `QUESTION_CONTENT_INTERPRETATION`과 `IMPLEMENTATION_PROPOSAL`로 구분했다. 자기소개에 본인 경험의 근거를 연결하는 방식도 W4의 제안이다. 가치관·개성·강점 세 가지를 모두 요구하지 않으며, 한 번의 행동만으로 고정된 성격을 단정하지 않는다.

문항에서 요구한 결과와 그 결과가 성공인지 여부도 구분한다. 도전 경험이 목표에 미달했다는 이유만으로 배제하지 않는다. 높은 성과 수치만으로 지속적인 노력이나 협업을 인정하지 않는다. 협업에는 갈등·리더 직책이 반드시 필요하다는 조건을 추가하지 않는다.

## 기업정보를 연결하는 범위

3월 국문 IT JD 10쪽에서 확인한 업무 영역과 우대 경험을 보조 맥락으로 사용한다. 소프트웨어 개발, DBMS·오픈소스, AI 앱, 반송 설비, 새 기술 활용은 각각 관련될 때 연결한다. 전부 충족해야 하는 목록이 아니다. 근거 위치는 [기업 출처 검증 JSON](../samples/verification/skhynix-source-review-2026-09-08.json)의 `ko-it-duties`, `ko-it-preference`, `ko-it-ai`다.

문항에 맞는 본인 행동 근거가 먼저다. 기업 우대 경험과 연결된다는 이유로 협업 근거가 없는 개인 프로젝트를 협업에 적합하다고 판정하지 않는다. 일반 데이터 정리 자동화를 반도체 반송 설비 경험으로 바꾸거나, Python을 썼다는 이유로 AI 경험으로 바꾸지 않는다. 다른 업계 경험도 해당 역량을 보여 주면 검토한다.

7월 기사에 나온 후속 채용 정책은 이 범위에 추가하지 않는다. 학위·전역·어학·코딩테스트 조건은 경험 추천 점수로 사용하지 않으며 지원 자격은 계속 별도 검토 대상이다.

## 근거 점검과 후속 질문

| 검토 표시 | 의미 | 처리 제안 |
|---|---|---|
| `SUPPORTED` | 제공 원문에 해당 내용을 뒷받침하는 구절이 있음 | 경험 ID·버전·발췌 위치를 연결 |
| `NOT_SHOWN` | 원문에서 필요한 내용을 찾지 못함 | 무엇이 더 필요한지 질문으로 남김 |
| `AMBIGUOUS` | 관련 표현은 있으나 주체·범위·연결 관계가 불명확함 | 팀과 본인의 기여 등을 구체적으로 확인 |
| `CONTRADICTED` | 원문에 반대되거나 충돌하는 내용이 있음 | 충돌을 표시하고 해당 주장을 추천 근거로 사용하지 않음 |

작성 당시 이 표시는 수동 검토에 사용했다. 이후 상세 추천 경로는 같은 점검 상태를 사용해 후보 상태를 결정한다. `NOT_SHOWN`은 경험하지 않았다는 뜻이 아니다. `SUPPORTED`도 실제 수행 사실의 독립 검증을 뜻하지 않는다.

소유권·제외 요청·버전·원문 위치 일치는 별도 근거 검사다. 유효하지 않은 발췌로 문항 충족을 주장할 수 없다. 내용 점검 항목을 잘게 나눈 개수 자체에 점수를 주지 않으며, 같은 근거를 여러 번 인용해 독립 증거처럼 부풀리지 않는다.

## 기존 가상 경험에 대조한 예시

아래는 `samples/w4_collaboration.json`의 원문을 직접 읽어 작성한 예시다. **추천 엔진이나 외부 LLM을 새 기준으로 실행한 결과가 아니다.** 수동 판단은 모델 평가용 승인 정답으로 등록하지 않았다.

| 가상 경험 / 검토 문항 | 원문에서 확인한 내용 | 추가 확인이 필요한 내용 |
|---|---|---|
| `episode-learning` / 전문성 | Python·공식 문서를 학습해 데이터 정리 코드에 적용했고, 파일 3개의 정리를 자동화함 | 얼마나 오래·여러 차례 학습했는지. 파일 개수는 학습 기간의 근거가 아님 |
| `episode-team-api` / 협업 | 본인이 회의를 진행하고 API 요구를 조율하며 역할을 나눈 행동 | 팀이 함께 정한 목표, 조율이 목표 달성에 어떻게 기여했는지, 소회. 오류 감소를 회의의 효과라고 단정하지 않음 |

따라서 기존 데모의 `DIRECT_MATCH`를 이 문항 초안의 판정으로 복사하지 않는다. 기존 데모와 이 문항은 요구 내용이 다르다. 확인되지 않은 기간·목표·감상을 가상 경험 원문에 덧붙이지 않고 부족한 근거를 표시했다.

## 완료한 범위와 다음 단계

문항 5개에 대한 내용 점검 10개, 원문에서 확보할 정보, 기업정보 연결 범위, 누락·모호함 처리와 가상 경험 대조 2건을 정리했다. 출처·문항·경험 발췌 참조를 검사했다.

원본 기준 JSON은 작성 당시의 설계·검토 기록으로 보존했다. 이후 [실행용 문항 자료](../epick_w4/criteria_catalog.json)를 통해 새 `/w4/recommend-from-raw`에 5문항·10점검을 연결했다. 일반 `/w4/recommend`의 문항 분석과는 별도 경로다. 모델 평가 정답·운영 선정 승인으로 전환한 것은 아니다.

후속 추출과 실제 모델 비교는 [근거 추출 안내](w4-evidence-extraction.md), 상세 점검의 실제 시연과 보완은 [v4 보고서](w4-review-v4-2026-09-09.md)에 있다. 목표·기간·난관·소회를 원문 구간에 보존하고 판단에 연결했다. 작은 가상 자료의 실험이며 사람의 의미 검토와 운영 품질 확정은 남아 있다. 기준 JSON의 `implementation_boundary`는 2단계 작성 당시 기록이며, 최신 위치는 [작업 순서](w4-workflow.md)를 따른다.
