## 2026-09-09 당시 진행 이력

이하 수치와 완료 표시는 그날의 기록이다. 현재 상태는 위 표를 따른다.

1. **기업 채용정보 수집·검증**
   해당 직무의 요구사항·우대사항·평가 방향을 확인합니다. 기존 역할 분담에서는 앞단 담당자가 수행하고 W4가 결과를 받습니다.
2. **경험 선택 기준 정리**
   자기소개서 문항이 요구하는 역량과 조건을 파악하고, 관련된 기업정보를 연결합니다. 각 기준에는 출처가 있어야 합니다.
3. **경험 원문에서 근거 추출**
   경험별로 본인의 역할·행동·결과를 찾아 정리합니다. 원문 위치와 문맥을 보존하고, 서로 다른 경험을 섞지 않습니다.
4. **근거 검사와 적합성 판단**
   추출한 내용이 원문과 일치하는지 검사하고, 그 행동이 문항의 기준을 충족하는지 의미를 비교합니다. 관련 있음·부분적으로 관련 있음·추가 확인 필요 등을 구분합니다.
5. **우선순위 결정과 추천**
   합의한 추천 기준에 따라 경험을 정렬하고, 추천 이유와 부족한 근거를 함께 반환합니다.

## 현재 위치

**채점기 개선 → 새 사례 재평가 → 두 모델 조합 시연 → 상세 문항 연결까지 진행했다.**
v4 실제 비교 336회, 조합 시연 52회, 상세 판단 보완 35회를 기록했고 테스트 216개가 통과했다.
추출 후보는 Gemma 12B B다. 경험 판단은 Qwen 14B A와 Gemma 26B B가 공동 최고이며,
문항·매칭 종합 최고점은 Gemma 12B B다. 필수 검사와 사람 검토가 끝나지 않아 운영 모델은 보류했다.
[최신 보고서](w4-review-v4-2026-09-09.md)에 점수의 한계, 실제 시연, 오류 보완과 원본 대조가 있다.
[팀 서비스 조사](w4-backend-integration.md)에서는 `feat/BE`의 구조 파일이 모두 비어 있어 API·인증·DB 명세를 확인하지 못했다.

| 단계 | 현재 상태 | 남은 작업 |
|---|---|---|
| 1. 기업 채용정보 수집·검증 | 제공된 SK하이닉스 자료의 공식 출처 대조 완료 | 공식 지원서 전체 문구·글자 수·필수 여부의 후속 대조. 미확인 조건은 개발을 막거나 경험을 제외하는 조건으로 사용하지 않음 |
| 2. 경험 선택 기준 정리 | 5문항·10점검 초안을 실행용 문항 자료로 연결 | 공식 문항 확보 시 차이를 검토. 정답·공식 평가표로 승인된 것은 아님 |
| 3. 경험 원문에서 근거 추출 | 새 6경험·30구간으로 A/B 재평가. Gemma 12B로 실제 추출 후 판단 모델에 전달 | 사람의 원문 분류 정답 검토, 실제 데이터·검색 연결 |
| 4. 근거 검사와 적합성 판단 | 원문 인용·문맥·기준 의미를 분리. 기간·목표·난관 등을 상세 점검에 적용하고 실제 재확인 | 미등록 동의 표현 검토, 역할 배정 오판 등 일반화 오류 개선 |
| 5. 우선순위 결정과 추천 | 일반 추천과 상세 문항 추천 실행. 세부 점검 개수를 가산점으로 중복 계산하지 않음 | 전체 품질·정렬 정책의 팀 검토, 운영 모델 확정, 서비스 인증·DB·검색 연동 |

**상세 기준 JSON + 추출 결과의 연결은 새 `/w4/recommend-from-raw`에서 구현했다.**
기간 없는 학습 경험은 전문성 문항에서 일부 부합으로, ‘꾸준히 배우는 태도’ 주제에서는 확인 필요로 남는 것을 실제 확인했다.
일반 `/w4/recommend`와 요구 내용이 다르므로 예전 DIRECT_MATCH를 상세 문항 판정으로 복사하지 않는다.

## 별도로 진행할 공급자 연결·모델 평가

1. **다른 공급자의 호출 연결:** 공통 JsonClient 규약, 생성 설정 기록, 가상 데이터 전송 제한을 만족하는 어댑터 연결.
2. **기존 항목의 실제 비교 평가:** 문항 해석·경험 매칭을 공통 정답·정책으로 채점하고 해당 범위의 최고점 모델 선정.
3. **원문 추출 정확도의 별도 평가:** 원문 구간의 종류·주체·서술 상태, 누락·잘못된 추출을 확인하는 별도 정답 사례와 지표를 마련해 비교.

기존 두 축과 원문 추출 점수를 임의로 합산하지 않는다. 현재 두 축의 평가 결과만으로 추출까지 최고 성능이라고 주장하지 않는다.
현재 로컬 모델 4개를 같은 조건에서 실제 비교했고 원문 추출도 별도 채점했다.
최종 모델 선정은 보류했다. 상용 공급자 API 비교에는 해당 어댑터·키가 필요하며 정답 기준 검토도 남아 있다.

## 진행 근거와 미확인 사항

1단계로 돌아와 제공된 SK하이닉스 자료의 공식 출처를 대조했다. Claim 6개의 내용과 적용 범위를 확인하고, 첨부 PDF 3개를 확보해 IT 직무와 FAQ를 읽었다. 상세 결과는 [검증 보고서](skhynix-source-verification-2026-09-08.md)와 [검증 JSON](../samples/verification/skhynix-source-review-2026-09-08.json)에 있다.

경험 추천의 작업 대상은 **2026년 3월 상반기 신입 IT 채용(R260521, IT 근무지 이천)**으로 설정했다. 기존 샘플과 직무기술서의 범위에 맞춘 기본 선택이다. 전문성·협업·도전·선택형 자기소개와 별도 직무 경험 기술 항목은 당시 공개된 재게시 자료에서 확인했다. **공식 지원서 전체 문구·필수 여부·글자 수의 최종 대조는 남아 있다.** 상세 내용은 [대상 채용·문항 확인 기록](w4-target-questions-2026-09-08.md)과 [문항 확인 JSON](../samples/verification/skhynix-question-scope-2026-09-08.json)에 있다.

사용자가 미확인 조건을 고정하지 않고 진행하도록 요청해 **2단계의 경험 선택 기준 초안을 작성했다.** 문항 5개에 대한 내용 점검 10개, 필요한 원문 정보, 기업정보 연결 범위와 가상 경험 대조 2건을 정리했다. [기준 설명](w4-question-criteria.md)과 [작성 당시 기준 JSON](../samples/criteria/skhynix-it-2026-march.draft.json)을 참조한다. 공식 문구·글자 수·필수 여부는 미확인으로 남기며 경험 제외·감점에 사용하지 않는다. 이후 별도 상세 추천 경로에 초안을 연결했으며 모델 평가 정답으로 승인하지 않았다.

**3단계의 경험 근거 추출 계약·구현과 모의 검증을 완료했다.** 원문 구간에 코드가 ID·위치를 붙이고, LLM 응답의 종류·주체·서술 상태를 검사해 역할·행동·결과와 목표·기간·난관·소회·상황을 구분한다. 가상 원문 4개·모의 분류 응답으로 원문 구간 19개와 Fact 12개를 구성했다. [추출 계약·실행법](w4-evidence-extraction.md)을 참조한다. API를 포함한 전체 147개 테스트가 통과했다.

이후 일반 문항의 **4단계·5단계 연결과 실제 시연**을 완료했다. 경험별 호출로 바꾸고 새 추출 Fact를 추천기에 전달해 본인 기여가 부족한 경험을 확인 필요로 반환했다. v4에서는 목표·기간·기여 관계를 다루는 상세 문항도 별도 경로로 연결했다.

호출 모델은 **여러 LLM을 공통 기준으로 평가한 뒤 최고 점수 모델을 선택**한다. 비교 평가와 호출 연결을 구현했고,
선정된 공급자·모델·설정 확인, 공동 1위·미평가·어댑터 부재 처리와 상세 문항 안전성 검증을 포함해 전체 216개 테스트가 통과했다.
Solar는 현재 구현된 전송 어댑터이며, 고정된 최종 모델이 아니다. [평가·선택 안내](w4-model-evaluation.md)를 참조한다.

현재 원문은 가상 자료이며 실제 모델 분류 응답과 이전 모의 응답을 별도로 보관한다.
실제 로컬 응답 수집·비교, 추출 예비 평가와 최종 추천 시연은 완료했지만 운영 모델 확정과 추천 품질의 사람 검토는 남아 있다.
두 평가 축(문항 해석·경험 매칭)에 추출 정확도를 합산하지 않는다.
모델 비교 평가기의 미승인 정답·가중치와 경험 추천 순위 정책은 별개다. 공식 지원서 확보도 후속 대조 항목으로 유지하며,
미확인 서식 조건을 강제하거나 다른 차수의 조건을 합치지 않는다.
